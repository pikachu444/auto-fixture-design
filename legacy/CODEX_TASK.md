# Codex 후속 개발 작업 지시

당신은 이 저장소의 파라메트릭 실험 지그 프로그램을 이어서 개발합니다. 사용자는 소재 시편 치수/물성을 넣으면 시험기·프린터 제약을 검사하고 지그를 수정하여 제작 전 오류를 발견하는 프로그램을 원합니다. 실제 재제작을 줄이는 것이 목적입니다.

## 먼저 확인할 문서

1. `START_HERE.md`, `EXECUTION_REPORT.md`
2. `planning/fixture_plan.md` 전체 및 두 acceptance_tests CSV
3. 실행 소스, `inputs/bending.json`, `outputs/results.json`

기획 문서와 실제 구현을 구분하세요. 이 저장소의 구현 완료 범위는 3점 굽힘 예제 하나입니다. 기획의 79개 제품 인수 검사는 미실행이며 이번 데모 검사 통과로 완료 처리하면 안 됩니다.

## 첫 번째 작업 단위

- 가상환경에서 의존성을 설치하고 데모/단위 테스트를 재실행하여 기준 결과를 재현합니다.
- 숫자/단위/지원범위 검증을 입력 스키마로 분리합니다. 하드코딩된 템플릿 치수가 입력에 노출되는 문제를 정리합니다.
- 굽힘 기능에 실제 입력 폼을 연결합니다. 형상만 보는 현재 HTML을 입력→검증→미리보기→파일 다운로드 프로그램으로 발전시킵니다. 판정과 근거, UNKNOWN 이유를 표시합니다.
- 시편 정보, 프린터 정보, 시험기 부품 정격 중 하나라도 불명확하면 제작 승인으로 올리지 않습니다. 프레임 정격만으로 시스템 하중을 승인하지 않습니다.
- 웹을 쓴다면 로컬 Python 백엔드(CadQuery)와 프런트엔드를 분리하고, 생성 작업 격리·타임아웃·파일 이름 검증을 구현합니다. 자연어 입력은 검증된 구조화 파라미터까지만 변환하고, 임의 Python 코드 실행으로 연결하지 않습니다.

## 순차 확장

1. 실제 장비/로드셀/공구 장착 인터페이스 프로파일 및 단위 처리. Zwick Z010 TH는 참조 장비이며 실물 구성은 미확인입니다.
2. 현재 지그를 체결 가능한 설계로 보완: 너트·와셔·장착 어댑터, 롤러 보유 구조, 공차, 처짐·접촉·크리프/층간 강도 평가. 현재 333.33 N은 시편에서 계산한 설계 요구 하중이며 출력 지그의 검증 정격이 아닙니다.
3. 압축, 인장, 반복 굽힘 템플릿을 각각 별도 규칙으로 추가. 반복 굽힘을 정적 굽힘 모델로 처리하지 말고 기획의 Instron E1000 후보 조건을 확인합니다.
4. 실제 프린터·소재·노즐·레이어·출력 방향 프로파일을 입력받고 PrusaSlicer CLI 어댑터를 만듭니다. 3MF 형상과 슬라이서 프로젝트를 구분합니다. 베드 적합성만 통과한 상태에서 G-code를 생산용으로 표시하지 않습니다.
5. 기존 파라메트릭 CAD를 연결할 명시적 파라미터 매핑 API. STEP에는 원본 CAD의 설계 이력이 없을 수 있음을 처리합니다.
6. 최종적으로 검증된 출력 시험편 쿠폰 → 치수 확인 → 장착 확인 → 승인된 단계 하중 시험 → 결과 환류 흐름을 구현합니다.

매 작업 단위마다 실행 가능한 결과, 변경 이유, 실제 수행 테스트, 남은 미검증 항목을 보고하세요. 기존 코드와 결과를 바탕으로 이어가며 제품 전체를 완료했다고 표현하지 마세요. 테스트 실패를 통과로 바꾸려고 설계 요구나 안전 기준을 낮추지 마세요.

## 첫 회차 완료 조건

기존 데모 재현, 입력 검증 개선, 굽힘 입력 UI, 실제 파일 다운로드, 자동화된 대표 정상/실패 시나리오, 업데이트된 실행 가이드까지 완료합니다. 이후 위 순차 확장을 진행합니다. 실물 없는 상태에서도 소프트웨어 검증과 모형 제작 자료 작성은 계속하되, 실물 확인이 필요한 판정은 UNKNOWN으로 남깁니다.
